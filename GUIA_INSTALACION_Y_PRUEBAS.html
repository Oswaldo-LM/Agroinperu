1. Requisitos Previos

  • Docker Desktop: Versión 4.20+ con motor Linux y Docker Compose v2.
  • Node.js: Versión LTS 18.x o 20.x (con npm v9+).
  • Git: Para control de versiones y sincronización de ramas.
  • Navegador Web: Google Chrome o Microsoft Edge.

5. Pruebas de Rendimiento con k6

Correspondiente a la subsección 3.x.3 Pruebas de Rendimiento de cada Sprint del Capítulo III.

5.1. Métricas y Criterios de Aceptación:

  • Carga Concurrente: 15 usuarios virtuales simultáneos (VUs).
  • Tiempo de Respuesta Promedio: Menor a 180 ms (avg < 180ms).
  • Percentil 95 (p95): Menor a 300 ms (p(95) < 300ms).
  • Tasa de Fallos: Menor al 1% (http_req_failed: rate < 0.01).

5.2. Comando de Ejecución vía Docker (Sin instalar k6 en Windows):

Desde PowerShell en la raíz del proyecto:

docker run --rm -i -v "C:\Users\lmore\Documents\AgroIn\backend\tests\performance:/scripts" grafana/k6 run /scripts/full_system_load.js

6. Solución de Problemas Frecuentes

SituaciónCausaSolución
k6 no conecta con la API Uso de localhost desde el contenedor Los scripts usan http://host.docker.internal:3000/api para comunicarse directamente con el host de Windows.
Conflicto con puerto MySQL 3306 MySQL local ya instalado en Windows El proyecto expone el puerto 3307 hacia el exterior para evitar cualquier colisión.
